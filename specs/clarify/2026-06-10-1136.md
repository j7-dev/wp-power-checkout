## Idea

規劃實作 PayNow 物流 & 電子發票功能，需要使用統一的接口 interface。

- PayNow 物流 → 必須實作 `ILogisticsProvider` 統一介面（與 ECPay Logistics / PAYUNi Logistics 平行）
- PayNow 電子發票 → 必須實作 `IInvoiceService` 統一介面（與 Amego / ECPay / ezPay 平行；視 API 能力決定是否加 ISupportsAllowance / ISupportsQuery）
- 不破壞現有介面；若 PayNow API 能力與介面有落差，用既有慣例處理（throw `\Exception('尚未實作')` 或回傳 WP_Error）

## 起始狀態判定

**Existing**（非 greenfield）。專案已有完整 specs 結構：
- Logistics 統一介面 `ILogisticsProvider`（10 methods），已有 2 個 provider：ECPay（`ecpay_logistics`）、PAYUNi（`payuni_logistics`）
- Invoice 統一介面 `IInvoiceService` + 選配 `ISupportsAllowance` / `ISupportsQuery`，已有 3 個 provider：Amego / ECPay（`ecpay`）/ ezPay（`ezpay`）
- PayNow 金流（體系 1）已完成（`Domains/Payment/Paynow/`）

## 知識來源盤點（Composition Analysis 前置）

### PayNow 電子發票（體系 3）— 完整度高
- 來源：專案內 `paynow` skill `references/invoice-api.md`（完整端點 + 欄位表）
- API：Bearer JWT-Token；`invoiceapi-prod.paynow.com.tw` / `invoiceapi-dev.paynow.com.tw`
- 端點：issue / cancel / allowance / cancel-allowance / GET invoices（查詢）/ POS 取號 / POS 開立
- 能力對映：issue→IInvoiceService::issue、cancel→IInvoiceService::cancel、allowance+cancel-allowance→ISupportsAllowance、GET invoices→ISupportsQuery
- 結論：PayNow 發票可實作 IInvoiceService + ISupportsAllowance + ISupportsQuery（與 ezPay 同等級）

### PayNow 物流 — paynow skill 未涵蓋（GAP），改由 woomp 既有實作 grounding
- ⚠️ **`paynow` skill 完全沒有物流 API**（只有金流體系 1/2 + 發票體系 3）。物流知識來源改用 woomp（MorePower Addon，`../woomp/includes/paynow-shipping/`）既有可運作實作。
- API（grounded from woomp）：
  - 建單：`POST {api_url}/api/Orderapi/Add_Order`（body `JsonOrder` = base64(TripleDES DES-EDE3 encrypt(JSON))）
  - 重新取號：`POST {api_url}/api/Orderapi/ReNewOrder`
  - 取消：`DELETE {api_url}/api/Orderapi/CancelOrder`（body LogisticNumber + sno + PassCode）
  - 查詢：`GET {api_url}/api/Orderapi/Get_Order_Info?LogisticNumber=&sno=`
  - 選店地圖：browser form-POST `{api_url}/Member/Order/Choselogistics`，returnUrl callback 回 storeid/storename/storeaddress
  - 列印標籤：per-service 端點（Order711 / OrderFamiC2C / OrderHiLife / PrintBlackCatLabel / Print711bulkLabel ...）
  - PassCode = `strtoupper(sha1(user_account + OrderNo + TotalAmount + apicode))`
  - 認證：user_account + apicode（apicode 為商家 API 密碼）；**TripleDES 固定 key/IV**（與金流 HMAC、PAYUNi AES-GCM、ECPay AES-128-CBC 全不同源）
  - 物流服務代碼：01=7-11店到店 02=7-11大宗 03=全家店到店 04=全家大宗 05=HiLife店到店 06=黑貓宅配 21=7-11冷凍C2C 22=7-11大宗冷凍 23=全家冷凍C2C 24=全家大宗冷凍
  - DeliverMode：01=取貨付款(COD) 02=取貨不付款
  - 黑貓宅配 DeliveryType：溫層（常溫/冷藏/冷凍 0003）

## Q&A

> ⚠️ 本 session 由 clarifier 以 sub-agent 執行，AskUserQuestion 不可用、無法即時向用戶提問。

- Q1: PayNow 物流 API 知識來源？（paynow skill 無物流 API）
  → A（預設）: **以 woomp（../woomp/includes/paynow-shipping/）既有可運作實作反推 API contract**。
    所有物流規格標記 `ASM(依 woomp 反推)`，端點/加密/欄位有實證；具體 Example 資料待 PayNow 官方文件 + sandbox 核對（GAP）。
- Q2: PayNow 物流選店流程如何對映 ILogisticsProvider 三段式介面？
  → A（預設）: **沿用三段式介面（與 ECPay / PAYUNi logistics 對齊，零介面破壞）**。
    get_store_selection→導轉 Choselogistics 地圖頁；parse_store_selection→收 callback 寫門市 meta；create_shipment→Add_Order 建單。
    print_document→per-service 列印端點；cancel_shipment→CancelOrder；query_shipment→Get_Order_Info；
    handle_status_callback→貨態查詢輪詢（woomp 是主動 query 非 webhook 推送，故 callback 退化為查詢補單；標 BDY）；
    create_return→woomp 無逆物流 API 證據 → throw `\Exception('尚未實作')`（既有慣例）。
- Q3: PayNow 電子發票能力範圍？
  → A（預設）: **IInvoiceService（issue/cancel）+ ISupportsAllowance（allowance/cancel-allowance）+ ISupportsQuery（GET invoices）**，
    與 ezPay 同等級。POS 取號/開立排除（一般 WooCommerce 電商不走 POS，GAP 後續）。

## 衍生決策（依預設推導）

- 介面破壞：**零**。Logistics 沿用既有 ILogisticsProvider（PAYUNi logistics 已證明可容第二 provider，PayNow 為第三）；Invoice 沿用 IInvoiceService + 兩選配介面（PayNow 為第四 provider）。
- 加密：PayNow 物流 = TripleDES DES-EDE3 固定 key/IV（自建 helper，與金流 HMAC / PAYUNi AES-GCM / ECPay AES-128-CBC 全不同源，不複用）；PayNow 發票 = 純 Bearer JWT-Token（無對稱加密）。
- order meta 前綴：物流 `_pc_paynow_logistics_*`、發票沿用 Invoice domain 既有 `_pc_issued_invoice_data` / `_pc_invoice_provider_id` 等共用 key（與 ezPay/ECPay/Amego 一致，僅 provider_id 不同）。
- 退貨能力：woomp 無 PayNow 逆物流 API 證據 → create_return throw 尚未實作（BDY/GAP）。
- 貨態通知：woomp 為主動查詢（query Get_Order_Info）非 webhook 推送 → handle_status_callback 在 PayNow 退化為「補查狀態」，無 ServerReplyURL 推送端點（BDY，待官方文件確認是否有 webhook）。
