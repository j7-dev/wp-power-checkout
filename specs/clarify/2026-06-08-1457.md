# Clarify Session 2026-06-08 14:57

## Idea

任務：規劃實作 **ezpay-invoice（ezPay 電子發票）** 功能，作為 Power Checkout plugin 的新發票 provider。

核心約束：**必須使用專案既有的統一發票接口 `IInvoiceService`**（與 Amego、ECPay Invoice 共用同一抽象層，不另起爐灶）。

ezPay = 藍新金流 NewebPay 旗下品牌；對應官方 EZP_INVI_1.2.1 手冊。重點差異：
- 加密：AES-256-CBC PostData_（HashKey 32 bytes / HashIV 16 bytes / PKCS#7 / hex 輸出）— 與 ECPay 的 AES-128-CBC 不同，AesCrypto 不能直接 reuse
- 回應驗證：CheckCode SHA256
- 全生命週期 API：invoice_issue / invoice_touch_issue / invoice_invalid / allowance_issue / allowance_touch_issue / allowanceInvalid / invoice_search
- 載具類別（手機條碼 0 / 自然人憑證 1 / ezPay 載具 2）、捐贈碼 LoveCode、課稅別 TaxType、零稅率
- endpoint 分測試（cinv.ezpay.com.tw）/ 正式（inv.ezpay.com.tw）

需要訪談釐清的需求面：1.範圍 2.開立時機 3.checkout 發票欄位 4.block checkout 5.B2B 6.測試策略

## Q&A（以推薦決策落地，標記 ASM）

- Q1 功能範圍 → A: **對齊 ECPay**（開立 issue + 作廢 invalid + 折讓 allowance(issue+invalid) + 查詢 invoice_search）。依據：既有兩個 provider（Amego/ECPay）能力一致；退款自動折讓 hook `maybe_issue_allowance_on_refund` 可直接複用 `ISupportsAllowance`；ezPay 特有的兩段式「等待觸發/預約自動」開立(touch_issue)與折讓兩段式確認(allowance_touch_issue) 列為非首期（支線）。
- Q2 開立時機 → A: **沿用既有 auto-issue 機制**（`woocommerce_order_status_{status}` hook + settings `auto_issue_order_statuses`）+ 後台手動。預設自動開立狀態 = `processing`（與 ECPay/Amego 一致）；預設自動作廢狀態 = `refunded`。
- Q3 checkout 發票欄位 → A: **沿用既有 provider-agnostic 表單**（`InvoiceParams` DTO + `InvoiceApp` Vue + `InvoiceParamsValidator`）。ezPay 載具類別映射至既有 `EIndividual`：手機條碼(barcode→ezPay CarrierType=0) / 自然人憑證(moica→CarrierType=1) / 雲端發票(cloud→ezPay 電子發票載具 CarrierType=2) / 紙本(paper→PrintFlag=Y)。捐贈(donate→LoveCode)、公司(company→Category=B2B)。不為 ezPay 做專屬 UI 調整。
- Q4 block checkout → A: **共用層自動涵蓋**（`BlocksInvoiceIntegration` 為 provider-agnostic，ezPay 啟用即套用）。本次不為 ezPay 額外做 block 工作。
- Q5 B2B 公司戶 → A: **納入首期**（B2C 個人/載具/捐贈 + B2B 公司統編）。注意 ezPay 特有金額性質：Category=B2B 時 ItemPrice/ItemAmt 為未稅、B2C 為含稅，開立時依 Category 正確換算 Amt/TaxAmt/TotalAmt。
- Q6 測試策略 → A: **mock 為主（CI 安全）+ sandbox 可選**。mock 覆蓋：AES-256-CBC 加解密 round-trip、CheckCode SHA256 驗章、issue/cancel/allowance/query 的 StatusManager 與冪等、金額計算(B2B 未稅/B2C 含稅)、載具映射、零稅率。sandbox(cinv.ezpay.com.tw) 用於端到端真實驗證(參照藍新 MPG 已用真實 sandbox 驗 crypto 的前例)。本機 PHPUnit 受限(見 memory) → 同時提供離線 PHP harness 驗純邏輯。
