# Clarify Session 2026-06-09 16:30

## Idea

規劃在 Power Checkout WooCommerce plugin 內實作 **PayNow 金流（支付方式）** 功能，必須沿用專案既有的「統一金流 Provider 介面」（`IPaymentProvider` via `AbstractPaymentGateway`）。走 AIBDD 需求訪談流程，產出結構化規格與分階段實作計劃。PayNow API 知識唯一來源為專案內 `paynow` skill。最接近的兩個參考實作為 PAYUNi UPP（導轉式）與 PAYUNi UNi Embed（內嵌式 iframe）。聚焦金流，發票標記為後續。

## 已自主決策（技術選型，不丟回用戶）

- gateway ID = `paynow`；domain 目錄 `inc/classes/Domains/Payment/Paynow/`（與 skill 範例命名空間 `J7\PowerCheckout\Domains\Payment\Paynow\Http` 一致）
- 整合形態 = 體系 1（REST PaymentIntent + Component SDK v2 iframe 站內付），結構同構於既有 `PayuniUniEmbed`（內嵌式）→ 抄 UNi Embed 目錄/生命週期。理由：skill concepts.md 第 2 節明示「WooCommerce / Power Checkout 新整合建議走體系 1」，且體系 1 一套即可完成建立付款意圖 / 退款 / 查詢，無需體系 2 舊版握手。
- ⚠️ 與範本關鍵差異：PayNow 體系1 比 UNi Embed **少一支 create-payment REST 端點**——PayNow SDK `checkout()` 直接由 SDK 與 PayNow 完成授權+3DS，後端只需「建 PaymentIntent → 收 Webhook」。
- gateway extends `AbstractPaymentGateway`（已 implements `IPaymentProvider` 7 methods）
- 加密：PayNow 體系 1 無對稱加密；Webhook 用 HMAC-SHA256（key=PrivateKey）。自建 `Shared/Helpers/WebhookVerifier`（與 PAYUNi AES-256-GCM 不同源，不複用 PayuniCrypto）
- 冪等鍵 meta `_pc_paynow_payment_intent_id`（PayNow `pp_xxx`，Webhook 反查主鍵）+ `_pc_paynow_trade_no`（商家 OrderNo / paymentNo，格式 `PCN{order_id}`）
- 退款路由：信用卡 / ATM 走 REST `POST /payment-intents/:id/refunds`（ATM 需 bankCode/bankBranchCode/bankAccount）；超商代碼/LINE Pay/ApplePay 視 PayNow 規格，不支援者 → `WP_Error('refund_unsupported')`
- 憑證（PublicKey / PrivateKey）存 `woocommerce_paynow_settings`，不寫死；sandbox 先行（`sandboxapi.paynow.com.tw` / `js.paynow.com.tw` env='sandbox'），prod 後補
