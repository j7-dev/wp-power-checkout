## 技術決策（clarifier 自行決策，非窄門）

統一抽象 `ILogisticsProvider`（鏡像 IInvoiceService）已定案，含 10 方法：
get_settings / get_store_selection（階段 A 導轉選店）/ parse_store_selection（選店回呼）/ create_shipment（階段 B 成立物流單）/ query_shipment / print_document / create_return / cancel_shipment / handle_status_callback / get_supported_methods。

核心 trade-off：兩階段選店抽象吸收「ECPay 暫存單三段（RedirectToLogisticsSelection → ClientReplyURL 回 TempLogisticsID → CreateByTempTrade）」與「PAYUNi ship_map 單段 + trade」差異。加密完全隔離於 provider（ECPay AES-128-CBC / PAYUNi AES-256-GCM）。callback 回應差異（ECPay AES-JSON 三層 / PAYUNi 200 OK）收進 provider。統一主鍵 `_pc_logistics_ref`。詳見 open-issue/logistics-execution-plan.md。

確認：既有 provider-settings.feature 已預留 `回應 data 包含 "logistics" 陣列`，settings API 已預備容納物流 provider。
