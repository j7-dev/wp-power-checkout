## 既有程式碼偵察結論（Composition Analysis）

現有 `EcpayAIO/` 為「半成品骨架」，證據：
- `ProviderRegister.php:24` 註冊被註解：`// EcpayAIO\Core\Init::register_hooks();`，`$gateway_services` 只含 Shopline
- `Service::set_properties()` 寫死綠界公開測試憑證（merchant 3002599 / hash_key spPjZn66i0OhqJsQ），prod/test 都用同一組
- `PaymentGateway::get_settings()` 回傳空陣列 `[]`（無欄位定義）
- `Settings::instance()` 指向不存在的 `PowerCheckoutSettings::instance()->payments->EcpayAIO` 路徑（現代系統用 `ProviderUtils::get_option()`）
- `Credit::render_after_billing_address()` 直接輸出字面 `TODO`
- `RequestParams::instance()` 引用了拼錯的 class `Services`（應為 `Service`），MetaKeys 儲存與 type-info 邏輯被註解
- callback 端點 `wp-json/power-checkout/ecpay-aio` 被引用，但無對應 REST handler（無 WebHook 類別）
- 無 Vue 設定頁、無現代 Settings DTO（`extends BaseSettingsDTO` + `ProviderUtils`）

架構對比：
- **舊 ECPay**：每付款方式各自獨立 gateway（Atm/Barcode/Credit/CreditInstallment/CVS/WebAtm 共 6 個），對應 6 個 block tsx 已存在；走 `before_order_received()` → `auto-form` template 自動 submit 跳轉綠界 AIO Cashier
- **Shopline 標竿**：單一 redirect gateway（`shopline_payment_redirect`），多付款方式由託管頁選擇；走 `before_process_payment()` 回傳跳轉 URL；HMAC webhook + StatusManager 狀態流轉

可重用的舊資產：`Service::get_check_value()`（CheckMacValue SHA256 演算法）、`RequestParams` AIO 參數 DTO 結構、`Utils\Base::urlencode()`（綠界 .NET urlencode 規則）、6 個 block tsx。

## ECPay API 事實（來自 ECPay-API-Skill）

- AIO 導轉式：CMV-SHA256，跳轉綠界 Cashier，最簡單（~60% 採用率）；callback：ReturnURL（Form POST 幕後，回 `1|OK`）、OrderResultURL（前景導回）、PaymentInfoURL（ATM/CVS/BARCODE 取號通知）
- ATM/CVS/BARCODE 有兩段 callback：先 PaymentInfoURL（取號成功 RtnCode=2 或 10100073），後 ReturnURL（實際付款 RtnCode=1）
- 退款（DoAction Action=R 退款 / Action=N 取消授權）**僅信用卡**；ATM/CVS/BARCODE/WebATM **不支援 API 退款**，需綠界後台或客服人工
- AIO callback RtnCode 為「字串」型別；callback 必須冪等（綠界最多重送 4 次）

## Q&A（用戶 2026-06-04 拍板）

- Q: D1 舊 code 去留？ → A: **A — 砍掉舊 EcpayAIO，重建於 Shared\Abstracts\AbstractPaymentGateway**。搶救 CheckMacValue / urlencode / RequestParams 結構 / 6 個 block tsx 可改寫。
- Q: D2+D3 架構與整合模式？ → A: **AIO 導轉 + ECPG 站內付兩者並存，每整合模式一個 gateway**（`ecpay_aio` + `ecpay_ecpg`）。付款方式作為 gateway 內設定，不切成獨立 gateway。
- Q: D4 付款方式範圍？ → A: **完整** — 信用卡（一次/分期/定期定額）、ATM、WebATM、CVS、BARCODE、ApplePay。
- Q: D5 退款範圍？ → A: **僅信用卡 API 退款**（AIO DoAction Action=R/N；ECPG ecpayment domain）。非信用卡標「需綠界後台人工」+ WC 手動退款。
- Q: D6 發票整合？ → A: **Amego + 綠界發票兩者並存**。綠界 B2C/B2B 發票新增為 Invoice domain 新 provider（`ecpay`），與 Amego 並列 `$invoice_providers`，後台可切換。
- Q: D-cred 憑證？ → A: 測試用綠界公開測試帳號；正式 MerchantID/HashKey/HashIV 由後台 Vue 設定頁填入存 `woocommerce_{gateway_id}_settings`，**不寫死於 code**。
