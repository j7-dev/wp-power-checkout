# 台灣電子發票概念 — 載具、捐贈、字軌、生命週期

光貿是電子發票「加值中心」：營業人透過光貿開立發票並上傳財政部。理解以下概念才能正確串接。

## MIG 4.0 路徑異動（2025-01-01）

財政部「電子發票資料交換標準訊息建置指引（MIG）」3.2.1 於 115/1/1 停用，光貿已於
2025-01-01 升級為 MIG 4.0。API 路徑異動：

| 功能 | 舊路徑（MIG 3.2.1） | 新路徑（MIG 4.0） |
|------|---------------------|--------------------|
| 開立發票（自動配號） | `/json/c0401` | `/json/f0401` |
| 作廢發票 | `/json/c0501` | `/json/f0501` |
| 開立折讓 | `/json/d0401` | `/json/g0401` |
| 作廢折讓 | `/json/d0501` | `/json/g0501` |
| 開立發票（API 配號） | `/json/c0401_custom` | `/json/f0401_custom` |

舊路徑目前尚可續用，**新整合一律用新路徑**。注意：`invoice_type` 回應欄位仍用
`C0401`/`C0501`/`D0401` 等 MIG 訊息代碼（這是財政部訊息類型，不是 API 路徑）。

## 發票生命週期

```
            開立                  作廢
   ┌──────────────────┐   ┌──────────────────┐
   │  f0401 / f0401_  │   │     f0501        │
   │  custom          │   │ （限當期、無折讓）│
   └────────┬─────────┘   └────────┬─────────┘
            │ 回 code:0 + 發票號碼   │
            ▼                       ▼
     [光貿收件 / 配號]        [標記待作廢]
            │                       │
            ▼  非同步上傳財政部       ▼
   invoice_status / invoice_query 輪詢 invoice_status
   1 待處理 → 2 上傳中 → 3 已上傳 → 31 處理中 → 32 待確認 → 99 完成 / 91 錯誤
```

折讓是另一條獨立鏈：`g0401` 開立折讓 → `allowance_status` 輪詢 → `g0501` 作廢折讓。

### 作廢 vs 折讓 — 怎麼選

| 情境 | 用哪個 | 說明 |
|------|--------|------|
| 整張訂單取消、發票還在當期、尚未有折讓 | **作廢發票 `f0501`** | 發票視同從未開立 |
| 跨期才發現要取消 / 已有折讓 / 部分退貨 | **開立折讓 `g0401`** | 折讓單沖抵金額，原發票保留 |
| 退貨退一部分 | **開立折讓 `g0401`** | 折讓只折該品項金額 |

> 自 114/1/1 起，經買賣雙方合意之退回或折讓，賣方營業人應開立電子發票折讓單依限據實上傳
> （`AllowanceType=2` 賣方折讓證明通知單）。

## 載具（Carrier）

載具是「儲存電子發票的媒介」，讓消費者不用拿紙本就能對獎。開立時用三個欄位描述：
`CarrierType`（類別）、`CarrierId1`（顯碼 / 明碼）、`CarrierId2`（隱碼）。

| 載具類型 | `CarrierType` | 顯碼 / 隱碼規則 | 驗證 |
|----------|---------------|------------------|------|
| 手機條碼（共通性載具） | `3J0002` | 手機條碼字串 | 正規式 `^\/[0-9A-Z\+\-\.]{7}$`；存在性用 `/json/barcode` API |
| 自然人憑證條碼 | `CQ0001` | 自然人憑證條碼 | 正規式 `^TP[0-9]{14}$` |
| 光貿會員載具 | `amego` | `a+手機號碼`（`^a09[0-9]{8}$`）或電子信箱 | — |
| 自家會員載具 | 自申請代碼 | 依貴公司向光貿申請的規格 | — |

光貿會員載具的擴充規則（顯碼 / 隱碼正規式）：

| 名稱 | 載具明碼 / 隱碼 | 正規表示式 |
|------|------------------|------------|
| 手機 | `a手機號碼` | `^a09[0-9]{8}$` |
| 信箱 | 電子信箱 | 一般電子信箱檢查 |
| 蝦皮 | `shopee_蝦皮帳號` | `^shopee_[A-Za-z0-9_\.]{5,30}$` |
| 露天 | `ruten_露天帳號` | `^ruten_[a-z0-9_\-]{4,24}$` |
| Yahoo 拍賣 | `yahoo_Y拍代號` | `^yahoo_[Yy][0-9]{10}$` |
| 8591 | `8591_買家編號` | `^8591_\d{5,7}$` |

**關鍵規則**：
- 載具 / 捐贈 / 列印三者互斥：帶載具就不能帶捐贈碼；列印發票（`PrintMark=Y`，自動配號預設列印）
  不可帶載具也不可帶捐贈碼。
- 光貿會員載具顯碼 / 隱碼帶電子信箱時**不會自動寄信**；要寄發票通知信須另填 `BuyerEmailAddress`。
- 載具發票（消費者用載具存）開立後**沒有紙本**；中獎前無法下載 PDF（`invoice_file` 回 code 53），
  中獎後才可下載。非載具發票可無限次下載。

## 捐贈（NPOBAN）

`NPOBAN` 填「受捐贈機關 / 團體愛心碼」。消費者選擇捐贈時，發票歸該團體。

- 捐贈碼須為財政部清單內有效碼（否則 `f0401` 回 3040136 格式錯 / 3040137 不存在）。
- 捐贈碼清單來源：財政部電子發票整合服務平台「受捐贈機關或團體捐贈碼清單」
  （`einvoice.nat.gov.tw` 開放資料，或定期下載 CSV）。
- 捐贈與載具互斥；捐贈發票不可列印。

## 統一編號（BuyerIdentifier）

- 沒打統編（B2C 一般消費者）：`BuyerIdentifier` 填 `0000000000`（10 個 0）。
- 打統編（B2B）：填買方 8 碼統編。統編有財政部公告的檢查碼邏輯
  （`fia.gov.tw` 營利事業統一編號檢查碼）。
- 公司名稱可用 `/json/ban_query` API 查（資料來源財政部，但管委會 / 會計事務所等不在資料集內，
  查不到不代表統編無效）。
- 打統編影響稅額計算：須分拆 5% 營業稅（見 `api-reference.md` 金額計算）；
  也只有打統編發票能用未稅單價（`DetailVat=0`）。

## 字軌（Track）與配號

「字軌」= 財政部配給營業人的發票號碼區段（英文 2 碼 + 8 碼數字，例 `MQ00000000`）。
字軌按「期別」分配（雙月一期，`Period` 0~5）。

三層字軌結構（`/json/track_all` 回傳）：

```
layer 1：財政部配給營業人的字軌
  └ layer 2：分配給光貿加值中心使用的字軌
      └ layer 3：營業人在後台「發票字軌列表」實際設定的字軌
```

字軌的 `category`：`1` 自動配號 / `2` API 配號。

| 配號方式 | 字軌類型 | 開立 API | 號碼來源 |
|----------|----------|----------|----------|
| 自動配號 | `category=1` | `f0401` | 光貿自動從字軌列表取下一號 |
| API 配號 | `category=2` | `f0401_custom` | 先用 `track_get` 取整段字軌，自己指定每張號碼 |

`track_get` 取號以「本」為單位，1 本 = 50 張。取到的字軌用 `track_status` 查配號進度。
字軌 `status`：`1` 使用 / `2` 停用 / `3` 過期 / `9` 用畢。

**絕大多數整合用自動配號即可**，不需碰字軌 API。API 配號適用「自己持有財政部字軌、
需離線開立後補上傳、或自管號碼池」的進階場景。`TrackApiCode`（f0401 選填）可在多組
字軌時指定用哪一組開立。

## 中獎與對獎

電子發票每雙月開獎一次。光貿提供：

- `/json/lottery_type`：獎項代碼定義（特別獎 1000 萬、特獎 200 萬、頭獎、二獎…）。
- `/json/lottery_status`：依年 + 期別查該公司開出的中獎發票清單。
- 開獎時程：例如 9-10 月（`Period=4`）發票於隔年（或當年）11/25 開獎，
  **建議 12/1 後**再查 `lottery_status`（雙月 1 號後）。
- `invoice_query` / `invoice_list` 的 `invoice_lottery` 欄位也帶該發票的獎項代碼。

## 熱感應機列印

開立時帶 `PrinterType`（熱感應機型號代碼），回應會多一個 `base64_data`：

- `PrinterType=1` Star mC-Print3 → base64 為 XML 列印格式。
- `PrinterType=2` 芯燁 XP-Q90EC / Xprinter 芯燁通用 → base64 為 ESC/POS。
- 把 `base64_data` 解碼後送進對應熱感應機即可印出發票。
- 0 元發票無法列印（沒有 QRcode 對獎聯），不回 `base64_data`。
- 已開立的發票可用 `invoice_print` 補印（`print_invoice_type=2`）；折讓用 `allowance_print`。

熱感應機編碼 `PrinterLang`：`1` BIG5 / `2` GBK / `3` UTF-8（不同機型支援不同，
詳見光貿後台「機型支援功能表」）。

## 與台灣其他電子發票服務商的差異

- 光貿是「加值中心」，非金流。若已用 ECPay / NewebPay / PAYUNi 收款，
  那些金流商也各自有電子發票模組——光貿是獨立的第三方電子發票選項。
- 光貿 API 風格：單一 `data` JSON 欄位 + md5 sign，**無 AES 加密**
  （不同於 ECPay 的 AES-128-CBC、NewebPay 的 AES-256-CBC）。
- 簽章只是「驗來源 + 防竄改」的 md5 hash，不是加密——`data` 本身是明文 JSON。
